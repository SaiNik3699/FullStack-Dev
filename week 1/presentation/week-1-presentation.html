Day 01 — Monday Foundations

How the web works

Learn
  • Client and server — who asks, who answers
  • DNS — turning a name into an IP address
  • HTTP — the agreed format of the conversation
  • Frontend vs backend — and which one you can trust
  • Install VS Code + Live Server, Prettier, ESLint
Build
  • Written notes on the whole request cycle
  • A diagram of a web request, nine steps end to end
docs/day-01-how-the-web-works.md
docs/web-request-diagram.svg
Steps 1–2 Client You type a URL. The browser asks DNS which IP address that name points at.
Step 3 DNS Answers with an address: 93.184.216.34. Cached at every level, so usually instant.
Steps 4–7 Server TCP + TLS handshake, then the HTTP request. The server matches a route and replies 200 OK.
Steps 8–9 Render The browser parses the HTML, fires a fresh request per CSS, JS and image file, then paints.
The point

The client is never trustworthy. Anyone can open DevTools and rewrite your JavaScript, so every rule that actually matters — who may delete this, what the price is — has to be enforced on the server. This one idea shapes all twelve weeks.

Day 01 — Monday Reference

HTTP on one sheet

Methods — the verb
GETGive me something. Changes nothing.
POSTHere is something new.
PUTReplace this entirely.
PATCHChange part of this.
DELETERemove this.
Status — learn the ranges, not the numbers
2xxIt worked. 200 201 204
3xxLook elsewhere. 301 302
4xxYou got it wrong. 400 401 403 404
5xxThe server got it wrong. 500 502
 
request →  GET /api/profile HTTP/1.1
           Host: localhost:3000
response → HTTP/1.1 200 OK
           Content-Type: application/json
           {"success":true,"data":{ ... }}
401 vs 403

This one catches everybody. 401 means “who are you?” — you are not logged in. 403 means “I know exactly who you are, and no.” — you are logged in and still not allowed.

Day 02 — Tuesday Structure

HTML — structure before style

Learn
  • Document skeleton: doctype, head, body
  • Headings h1–h6 as an outline
  • Text: p, strong, em, br, hr
  • Links: absolute, relative, mailto:, #anchor
  • Images and meaningful alt text
  • Lists: ul, ol, dl — and when each is right
  • Tables: thead, tbody, th scope, caption
Build
  • A personal bio page with no stylesheet at all
  • Every default style you see is the browser’s, not yours
client/steps/day-02-bio-html-only.html
<table>
  <caption>Week 1 plan</caption>
  <thead>
    <tr><th scope="col">Day</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Mon</th></tr>
  </tbody>
</table>
Gotcha

Headings are an outline, not font sizes. Never skip h2 to reach h4 because you wanted smaller text — that is CSS’s job. Screen readers navigate by heading level, and a broken outline is a broken map. One h1 per page.

Day 03 — Wednesday Meaning

Forms and semantic tags

Learn
  • header nav main section article aside footer
  • Every one renders like a div. The difference is meaning.
  • label / input pairing via for and id
  • fieldset + legend to group related inputs
  • Input types: text, email, tel, radio, checkbox, select, textarea
  • Native validation: required minlength pattern
  • GET vs POST — data in the URL, or in the body
Build

  • Validation that works with zero JavaScript
client/contact.html
client/css/components/form.css
<!-- for="email" must match id="email" -->
<label for="email">Email</label>
<input type="email" id="email"
       name="email" required />
Real bug

A pattern that fails to compile is silently ignored — no error, no warning, and the field then accepts anything. Browsers compile it with the regex v flag, where ( ) - must be escaped inside a character class. This exact bug shipped in the Week 1 code and was only caught by testing a value that should fail. Always test the rejection, not just the acceptance.

Day 04 — Thursday The box model

CSS — and the one line that fixes everything

Learn

  • Specificity — and why shallow selectors win long-term
  • Colour, and naming tokens by role, not appearance
  • Units: px fixed, rem from root, em from parent, %, ch

content-box → 350px on screen
border-box  → 300px on screen
Thursday

The most useful line of CSS you learn this week: *, *::before, *::after { box-sizing: border-box; }
The browser default makes padding and border push a box outward, which is why your three “33% wide” columns stop fitting the moment you add padding. With border-box, the number you write is the number you get.

Day 05 — Friday Layout

display, position, Flexbox

Learn
  • display: block, inline, inline-block, flex, none
  • position: static, relative, absolute, fixed, sticky
  • Flexbox’s two axes — and that they swap
  • justify-content follows the main axis
  • align-items is always perpendicular to it
  • flex: grow shrink basis, and gap over margins
  • flex-wrap — responsive before media queries exist
Build
  • A navbar: brand left, links right, vertically centred
  • A card row that wraps 3 → 2 → 1 with no media query
/* the entire navbar */
.site-header__inner {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
/* cards that wrap, and a bottom-pinned link */
.card-row { display: flex; flex-wrap: wrap; gap: 1.5rem; }
.card     { flex: 1 1 17rem; flex-direction: column; }
.card__link { margin-top: auto; }
Gotcha

Almost every “why won’t this centre?” bug is the axes. Set flex-direction: column and justify-content silently becomes vertical while align-items becomes horizontal. Draw the two axes on paper once and the confusion stops for good.

Day 06 — Saturday Build day

Ship the finished page

No new concepts today. Saturday is for assembling everything from Monday to Friday into one page you would actually show someone.

Done when
  • The bio page is styled end to end, header to footer
  • The navbar sticks, the cards wrap, the table scrolls on a phone
  • Every image has real alt text
  • Every form input has a real <label>
  • Tab through the whole page — the focus ring is always visible
  • No horizontal scrollbar at any width down to 375px
Open DevTools and
  • Network tab, then reload. Count the requests. One page is never one request.
  • Elements tab, pick any element, read the box-model diagram on the right.
  • Click the little flex chip to overlay the axes on the page.
  • Break it: delete box-sizing: border-box and reload. Thursday’s lesson, in one keystroke.

server/ ├─ routes/       "which URL am I?"
        ├─ controllers/  "read req, send res"
        └─ services/     "fetch the data" → Mongoose, wk 8
Why now

Splitting route → controller → service on day one is what makes Week 8 painless: swapping a JSON file for MongoDB touches exactly one file, because nothing above the service layer knows where the data came from.
